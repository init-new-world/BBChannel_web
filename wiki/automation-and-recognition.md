# 自动化流程与图像识别机制

> 注意：本项目仍处于实验/持续演进阶段，离线夹具测试不能完全替代在目标模拟器、游戏区服与分辨率布局下的实机验证。所有识别逻辑均依赖匹配的素材资源与规范的 1280×720 归一化画面。

## 全流程阶段与恢复

全流程刷本（`battle.run`）包含 `assist`（选助战）→ `prepare`（编队/出击）→ `battle`（战斗执行）→ `completion`（结算与再战）四个阶段：

- **入口模式**：支持 `current`（从当前画面自动识别阶段续接）、`free_quest`（自由本）、`main_story` / `ooku`（主线/大奥剧情节点确认、跳过剧情及关闭不可进本提示）、`interlude`（幕间物语）。
- **中途续接与恢复**：
  - `entry_mode=current` 启动时会检测当前处于助战、编队、战斗还是结算界面并直接衔接；若停在战斗中，当前波次会在首回合结束读取右上角 `phase_1/2/3` 后自动对齐跳过已过波次。
  - 各阶段内置断网通信重试弹窗识别；开启 `gameCrushRestart` 或画面冻结看门狗 `stuckRestart`（默认检查间隔 30 秒，可配 1–600 秒）后，遇到超时或卡死会自动重拉游戏并按 `max_restarts` 上限尝试恢复。

## 助战识别与筛选

- **多再临/灵衣头像匹配**：按从者标准名加载 `assets/servantface/{名称}_*.png` 全部再临阶段与灵衣模板进行多尺度+遮罩匹配，并按置信度去重。
- **职介页签切换**：遵循原版 `chooseRightClass` / `checkChoosedClass` 规则。已选中目标职介或好友页签时保持不动；`allNotSkip` 仅保留 ALL/推荐页签（索引 0 与 -1），不会阻止纠正其他错误职介；仅礼装与不识别模式不切职介。每次切换最多尝试 3 次双击并带取消检查点。
- **仅好友早刷（`onlyFriendAssist`）**：在当前列表至少滑动 2 次后，若无候选且右侧未检测到 `friend.png` 标记，则提前触发列表刷新，每次刷新重置计数并记录 `friend_boundary_hits`。
- **主动与附加技能（`skillsLevel`）**：保存 3 个主动技能 + 最多 5 个附加技能的最低等级（0–10，0 为不要求）。CNTW 布局仅支持 3 个附加槽，为第 4/5 槽配置非零要求会被校验拒绝。检查附加技能时会验证视图切换、逐槽识别、切回主视图并复核候选身份。
- **从者等级与排序**：`servantLevel > 1` 时会校验列表排序表头为 `levelorder.png` 或 `loadorder.png`（必要时点击排序切换最多 3 次），并使用较短滑动步长避免裁切头像上方的 `Lv. X/Y`。
- **礼装与冠位三槽模式**：支持普通模式与冠位助战（`冠位助战`、`冠位助战仅礼装`）。冠位模式保留原版三槽位布局（`normal` / `kizuna` / `houshuu`）、逐槽满破星标校验以及 1/3 号位礼装调换检测；`noGrandRefresh` 在滚动触达非冠位区域时触发刷新。
- **开跑前预检（Pre-Run Report）**：`GET /api/settings/{name}/pre-run-report` 与 `POST /api/settings/pre-run-report` 检查前排未满 3 人、提醒国服/台服关闭战斗字幕、汇总生效与无效的助战条件，并为托勒密（`arts`）、妖兰（`buster`）、U-奥尔加玛丽（`u_olga`）自动推导默认特殊过滤选项。

## 编队检查与操作延时

- **编队校验（`battle.prepare`）**：通过 `goldBack` / `silverBack` / `copperBack` / `blackBack` 判断编队画面是否正处于礼装背面视图并等待翻回从者头像；过渡帧导致 `>= 2` 槽位不匹配时自动重试一次，同时自动跳过战前剧情与芙芙加载界面。
- **操作延时语义（`intervalBF` / `intervalAF`）**：作用于任务局部上下文中的**每次设备点击或滑动前后**（而非每场战斗前后），默认前 0s、后 0.1s（后置最小 0.1s，上限 600s）。手动操作、截屏和诊断任务不继承该延时；识别等待参数（`intervalAFswipeAssist`、`intervalBFchooseCard`）独立生效。

## 战斗执行、指令卡与异常恢复

- **技能与条件块**：
  - 支持条件技能块 `["Start", mode, checks]` 或带 NP 条件 `["Start", mode, checks, ["np", ...]]` 到 `["End"]`，用于常规回合与波次额外回合（`extraSkill`）。NP 条件（0–300，`≥`/`≤`）在打开指令卡前评估并与手牌条件逻辑与；空/全假掩码跳过发牌识别。
  - 同一波次内执行换人后，该波次后续回合与额外回合会自动截断换人前技能及重复换人指令，进入下一波次重置保护。
  - 自动处理技能冷却/封印检查，以及关闭“无法使用”、从者详情或误开指令卡界面。
- **指令卡识别与回退**：
  - 结合助战角标（`assist.png`）准确区分双助战同名从者与无名助战，同时识别每张卡的 `weak` / `resist` 克制关系与行动受阻状态文本。
  - 策略选卡遵循严格匹配 → 放宽暴击星阈值（`posBak`）→ 保留预选宝具并按默认评分器（`select_command_cards_default`）补足的三级回退；条件检查仍要求严格匹配。
  - 若有未阻挡指令卡无法识别从者，自动返回战斗界面通过前排职介图标与状态头像（含半块回退与终次 `Lancer -> 堂吉诃德` 回退）重认前排后重新开卡。
  - 选完含宝具组合后若返回键未消失，会检测宝具是否被封印/定身并在当回合排除不可用宝具重新出卡（最多 3 轮）。
  - 额外回合若检测到前排阵容变动，自动合成可用前排自由技能并按默认评分器选卡。

## 结算、绊满停机、AP 恢复与掉落识别

- **结算与再战**：自动关闭掉落礼装详情、处理好友已满、跳过战后剧情，非连续关卡可从终局地图重新进本。
- **绊满停机与排除位**：`fullFriendshipStop` 开启时，遇到 `jbMax` 或 `jblevel10` 均停机；`ignoreFriendship` 可配置 1–5 结算站位（不含助战）对 `jbMax` 区域打掩码忽略，但触发 `jblevel10` 羁绊升级弹窗时仍会停机。
- **AP 与苹果恢复**：`clearAP` 在跑完目标次数后继续清体直至 AP 不足或达到 `max_clear_runs`（默认 100）。`allowOtherApple` 按金/银/蓝/铜顺序回退（绝不吃圣晶石），使用颜色校验过滤 0 库存变灰图标，并在查找蓝/铜或回退金/银苹果时自动拖动滚动条。
- **两阶段掉落识别（Drop Stop）**：严格复刻原版 `getDropTemp` / `checkDrop` 规则：先以彩色模板在阈值 0.65 全图搜候选（禁用隐式 Alpha 遮罩），再对每个候选切出中心四分之一区域以灰度在阈值 0.65 复核并校验中心平方偏移阈值 `min(50, max(30, h / 193 * 50))`，仅通过双重验证的候选计入跨场次统计。

## 活动与日常工作流

控制台“活动”页签内置了多个独立任务流：
- **无限池（Lottery）**：抽池、礼物箱狗粮堆叠数识别与筛选领取，支持仓库爆满后自动保管/贩卖/强化溢出恢复。
- **情人节交换（Chocolate）**：横幅采集、性别筛选与批量交换。
- **挖矿（Digdig）**：28 格棋盘与 18 交点识别、一键与筛选循环。
- **狗粮与养成（ExpBall）**：21 格保管室、从者/指令纹章贩卖、礼装搓丸子与满级锁定/标记、友情池自动锁卡（含莉莉/哈贝喵/白野开关与自定义目标）、从者定向强化与自动再临/圣杯突破，以及非友情池 4–5 星金卡与已刻印纹章锁卡保护。
- **素材查询与本地笔记**：内置掉落素材查询与本地记事本。
